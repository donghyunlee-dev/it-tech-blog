# 🛡️ AI 정보 보안 기본 지침서

## 목적

본 지침서는 임직원이 AI Agent, 생성형 AI, 코드 작성 도구, 문서 작성 도구를 사용할 때 회사 정보와 개인정보를 보호하기 위한 기본 원칙을 정의합니다.

AI는 문서 작성, 코드 개발, 데이터 분석, 업무 자동화에 활용할 수 있으나, 회사 정보와 고객 정보가 외부로 유출되지 않도록 사용 범위와 금지 기준을 명확히 준수해야 합니다.

---

# 🔐 기본 원칙

AI 사용 시 다음 원칙을 우선 적용합니다.

- 회사 정보는 기본적으로 외부 공개가 불가능한 정보로 취급합니다.
- 개인정보, 고객 정보, 재무 정보, 내부 정책, 미공개 정보는 AI에 입력하지 않습니다.
- 민감 정보가 포함된 파일은 AI에 첨부하거나 읽게 하지 않습니다.
- 승인되지 않은 외부 API, 메일, 메신저, 저장소, 업무 시스템은 AI Agent가 자동으로 연결하지 않습니다.
- AI가 생성한 결과는 검토 없이 외부에 공유하지 않습니다.
- AI 결과는 참고 자료이며, 최종 판단과 책임은 사용자에게 있습니다.
- 법률, 세무, 의료, 인사 평가 등 전문 판단이 필요한 영역은 담당 부서 또는 전문가 검토를 거쳐야 합니다.

# 📎 파일 첨부 기준

AI에 파일을 첨부하기 전 다음 기준을 확인합니다.

## 첨부 금지 파일

- 개인정보가 포함된 엑셀, CSV, PDF, 이미지
- 고객 주문, 배송, 정산, 상담 데이터
- 내부 시스템 접속 정보가 포함된 문서
- 서버 로그 원문
- 에러 로그에 토큰, 쿠키, 세션 정보가 포함된 파일
- 계약서, 견적서, 세금계산서 원문
- 미공개 정책, 전략, 기획 문서
- 인사 평가, 급여, 근태, 채용 관련 자료
- 외부 반출 승인을 받지 않은 회사 문서

## 첨부 가능 파일

- 개인정보가 제거되어 있음
- 고객 식별값이 제거되어 있음
- 회사 내부 식별 정보가 제거되어 있음
- 외부 공개가 가능한 수준으로 정리되어 있음
- 민감 정보가 샘플 값으로 대체되어 있음
- 보안상 문제가 없다는 검토를 마침

## 파일 첨부 전 점검

```text
개인정보가 포함되어 있는가?
고객 정보가 포함되어 있는가?
토큰, 비밀번호, 키가 포함되어 있는가?
내부 URL 또는 서버 정보가 포함되어 있는가?
원본 재무·회계 데이터가 포함되어 있는가?
미공개 정책 또는 전략이 포함되어 있는가?
외부에 공개되어도 문제가 없는가?
```

하나라도 해당하면 첨부하지 않습니다.

# 🔌 외부 연결 및 Agent 권한 기준

AI Agent는 파일, API, 메일, 메신저, Git 저장소, 업무 시스템에 접근할 수 있으므로 일반 대화형 AI보다 더 엄격하게 관리합니다.

## 자동 연결 금지

AI Agent가 다음 작업을 수행하기 전에는 사용자의 명시적 승인이 필요합니다.

- 외부 API 호출
- 메일 발송
- 메신저 전송
- Git push
- Pull Request 생성
- Issue 생성 또는 수정
- Jira 티켓 변경
- Confluence 페이지 수정
- Google Drive, OneDrive, S3 등 외부 저장소 접근
- 데이터베이스 접속
- 운영 서버 접속
- 배포 실행
- 파일 삭제
- 권한 변경
- 비용이 발생하는 클라우드 리소스 생성

## 승인 원칙

AI Agent가 외부 시스템에 연결하거나 데이터를 전송해야 하는 경우, 실행 전 다음 내용을 사용자에게 확인해야 합니다.

```text
어떤 시스템에 연결하는가?
어떤 데이터를 전송하는가?
어떤 변경이 발생하는가?
되돌릴 수 있는가?
비용이 발생하는가?
권한 또는 보안 영향이 있는가?
```

사용자가 명확히 승인하지 않은 경우 실행하지 않습니다.

# 🧠 프롬프트와 출력 보안

## 프롬프트 작성 원칙

프롬프트에는 최소한의 정보만 입력합니다.

좋은 예:

```text
주문 상태 변경 API의 예외 처리 방식을 개선하고 싶습니다.
아래는 개인정보를 제거한 샘플 구조입니다.
```

나쁜 예:

```text
실제 고객 주문 데이터와 오류 로그를 첨부합니다.
이 내용을 보고 원인을 찾아주세요.
```

## 출력 검토 원칙

AI가 생성한 결과는 다음 기준으로 검토한 뒤 사용합니다.

- 개인정보가 포함되어 있지 않은가?
- 내부 정보가 외부 공개 문서에 포함되어 있지 않은가?
- 사실이 검증되었는가?
- 출처가 필요한 내용에 출처가 있는가?
- 법률·세무·의료·인사 판단을 확정적으로 표현하지 않았는가?
- 경쟁사 비방 또는 확인되지 않은 비교 내용이 없는가?
- 보안상 민감한 절차가 과도하게 노출되지 않았는가?

# 🏢 회사 정보 보호 기준

회사의 내부 정보는 AI 학습 데이터, 외부 공유 자료, 공개 문서로 활용하지 않습니다.

## 금지 사항

- 회사 문서를 외부 AI 서비스에 원문 그대로 입력
- 내부 고객 데이터를 AI 학습용 데이터로 사용
- 내부 API 명세를 외부 AI에 입력
- 운영 로그를 원문 그대로 첨부
- 장애 대응 상세 절차를 외부에 공개
- 미공개 프로젝트 내용을 외부 도구에 입력
- 회사 내부 정책 초안을 외부 AI로 검토
- 승인되지 않은 AI API에 회사 데이터를 전송

## 허용 가능한 사용

- 개인정보와 회사 식별 정보를 제거한 샘플 데이터 사용
- 공개 가능한 수준의 일반화된 기술 질문
- 내부 값을 제거한 에러 메시지 분석
- 실제 시스템명을 제거한 구조 설계 검토
- 외부 공개 가능한 문서 초안 작성
- 가상의 예시 데이터로 코드 샘플 생성

## 코드 입력 기준

AI에 코드를 입력할 때 다음 정보가 포함되지 않도록 합니다.

- DB 접속 정보
- API Key
- Access Token
- Refresh Token
- Secret Key
- 인증서
- 쿠키
- 세션 값
- 운영 서버 주소
- 내부망 주소
- 보안 그룹 정보
- 실제 사용자 데이터
- 실제 고객 주문 데이터

## 로그 입력 기준

로그를 입력하기 전 다음 값을 제거합니다.

```text
Authorization Header
Cookie
Set-Cookie
Session ID
JWT
API Key
DB URL
DB Username
DB Password
Internal IP
Customer ID
Email
Phone Number
Order Number
```

## 코드 생성 결과 검토

- 비밀 정보가 코드에 하드코딩되어 있지 않은가?
- 입력값 검증이 있는가?
- 인증·인가 처리가 누락되지 않았는가?
- 로그에 민감 정보가 남지 않는가?
- 외부 API 호출이 승인된 범위 안에 있는가?
- 파일 삭제, 권한 변경, 배포 실행이 자동으로 수행되지 않는가?

- 주문 상세 원본

- 추가 검증 필요성

# 🧭 기본 판단 기준

판단이 어려운 경우 다음 기준을 적용합니다.

```text
외부에 공개되어도 문제가 없는가?
개인을 식별할 수 있는가?
고객이나 거래처를 식별할 수 있는가?
회사 내부 시스템을 추정할 수 있는가?
보안 설정이나 운영 구조가 드러나는가?
실제 업무 데이터인가?
승인된 AI 도구인가?
승인된 연결인가?
```

하나라도 명확하지 않으면 AI에 입력하거나 연결하지 않습니다.

# 📊 유명 테크 블로그 비주얼 품질 비교분석

## 🎯 목적

방문자는 코드나 기능 명세를 보고 블로그를 판단하지 않는다. **첫 화면의 레이아웃 비율, 이미지 배치, 폰트, 컬러**만으로 "계속 볼지/나갈지"를 몇 초 안에 결정한다. 기능(목록·검색·댓글)이 아무리 잘 작동해도, 화면이 접속하기 꺼려지고 글을 찾기 번거롭고 읽기에 불편하며 색감이 어색하다면 사용률은 낮아진다. 이 문서는 이전 버전(기능 구조 중심 비교)을 대체해, **오직 시각적 완성도**만을 기준으로 국내 기업 기술 블로그 5곳을 재비교한다. 특히 **"AI가 만든 듯한 느낌"이 나는 화면은 신뢰도를 깎아먹는 안티패턴**으로 별도 취급한다.

- 관련 문서: [design-system.md](design-system.md), [design-benchmark.md](design-benchmark.md)(기능 구조 벤치마킹 — 이 문서와는 관점이 다름), [../product/prd.md](../product/prd.md)
- 조사 방법: 2026-09-17, 각 블로그의 홈/목록/게시글 상세 화면을 직접 열람·스크린샷으로 확인. 아래 서술은 실제로 관찰된 화면 요소(색상, 폰트, 이미지 재사용 여부 등)에 근거한다.

## 🧪 평가 관점

| 관점 | 살펴본 것 |
|---|---|
| 레이아웃 비율 | 여백/그리드 비례, 텍스트 대 이미지 비율, 한 화면에 담기는 정보량이 과하거나 허전하지 않은가 |
| 이미지 배치 | 썸네일의 일관성(같은 크기·같은 톤인가), 재사용 여부, 실제 콘텐츠와의 관련성 |
| 타이포그래피 | 제목/본문 위계, 줄 길이·행간, 폰트 페어링의 통일성 |
| 컬러 | 브랜드 컬러의 일관성, 대비(가독성), 색이 과하거나 밋밋하지 않은가 |
| **AI 안티패턴** | 아래 체크리스트 참고 |

### 🤖 "AI가 만든 느낌" 안티패턴 체크리스트

실제 서비스 화면에서 자주 발견되는, 사람이 공들여 만들지 않고 자동/양산형으로 찍어낸 듯한 인상을 주는 신호들이다.

- 같은 스톡형 벡터 아이콘·일러스트를 서로 다른 글에 그대로 재사용
- 보라색/파란색 계열 그라디언트 블롭이나 글래스모피즘 카드를 목적 없이 남발
- 한 게시물에 해시태그를 10개 이상 기계적으로 나열(키워드 스팸형 태깅)
- 같은 페이지 안에서 한쪽은 공들인 카드 디자인, 다른 쪽은 스타일이 전혀 안 입혀진 날것 텍스트 목록이 뒤섞여 있음(초안과 완성본이 뒤섞인 듯한 인상)
- 화면 전반의 여백·정렬이 그리드 없이 제각각이라 "템플릿을 대충 채운" 인상을 줌

## 1️⃣ 토스 기술 블로그 (toss.tech)

- **레이아웃 비율**: 리스트 각 행이 텍스트(좌, 약 55%) + 썸네일(우, 약 45%)로 일정하게 분할되어 스크롤해도 리듬이 깨지지 않음. 상단 캐러셀은 화면 폭 대비 여백이 넉넉해 답답하지 않음.
- **이미지 배치**: 모든 썸네일이 파랑·초록·보라 톤의 아이소메트릭 3D 도형 일러스트로 통일되어 있고, 글마다 도형 배치만 달라 "같은 브랜드 화보집"처럼 보임 — 재사용이 아니라 **의도된 브랜드 일러스트 시스템**.
- **타이포그래피**: 자체 서체(토스 전용 서체 추정)로 제목은 굵고 크게, 본문은 한 줄에 약 30~35자로 끊겨 읽기 편함. 본문 중 핵심 문장을 파란색 볼드로 강조해 스캔하기 쉬움.
- **컬러**: 흰 배경 + 포인트 블루 한 가지로 절제. 채도 높은 색을 남발하지 않아 시각 피로가 적음.
- **AI 안티패턴 여부**: 없음. 오히려 반대로 "브랜드가 손으로 그린 듯한" 일관된 아트워크가 신뢰도를 높임.
- **총평**: 5곳 중 시각적으로 가장 "돈 들여 만든 티가 나는" 블로그.

## 2️⃣ 우아한형제들 기술블로그 (techblog.woowahan.com)

- **레이아웃 비율**: 상단 민트색 히어로 배너 이후, 목록 영역은 **썸네일이 전혀 없는 순수 텍스트 리스트**(날짜+작성자+굵은 제목+1줄 요약)만 반복된다. 여백은 넉넉하지만 시각적 앵커가 없어 스크롤할수록 단조롭다.
- **이미지 배치**: 목록에는 이미지가 아예 없고, 게시글 상세에서만 캡처 화면(이슈 트래커 스크린샷 등)이 등장한다. 첫인상(목록 화면)에서 이미지 부재가 "글이 많다"는 느낌보다 "밋밋하다"는 인상을 먼저 준다.
- **타이포그래피**: 제목이 크고 굵어 가독성 자체는 좋으나, 폰트가 시스템 기본 산세리프에 가까워 브랜드 개성은 약하다.
- **컬러**: 히어로 배너의 민트색을 제외하면 전체가 흑백에 가깝다. 절제라기보다 **색을 아예 쓰지 않은 쪽**에 가까워 카카오·토스 대비 화면이 심심하다.
- **AI 안티패턴 여부**: 없음(오히려 정반대로 사람이 손댄 흔적이 적어 "미완성 게시판" 느낌). 다만 이미지 부재가 방문 매력도를 떨어뜨리는 별도의 약점이다.
- **총평**: 콘텐츠 발행량과 태그 구조는 훌륭하지만, **첫 화면의 시각적 매력(썸네일 부재)만 놓고 보면 5곳 중 가장 밋밋**하다.

## 3️⃣ 카카오테크 블로그 (tech.kakao.com)

- **레이아웃 비율**: 홈 히어로는 "Kakao / Tech / Knowledge / Events / Support / Careers" 등 단어를 알약(pill) 모양 칩으로 자유롭게 흩뿌린 콜라주 구성 — 그리드에 얽매이지 않은 과감한 배치.
- **이미지 배치**: `/blog` 목록의 썸네일 톤이 글마다 크게 다르다. if(kakao) 컨퍼런스 글들은 짙은 남색 배경의 세련된 키비주얼(구체·와이어프레임 그래픽)을 쓰는 반면, 바로 옆 카드는 GitHub 스크린샷에 빨간 손그림 화살표만 얹은 캡처 이미지다. 같은 그리드 안에서 "전문 디자이너가 만든 것"과 "급하게 캡처한 것"이 섞여 **일관성이 깨진다**.
- **타이포그래피**: 큰 사이즈의 굵은 산세리프로 제목 위계는 뚜렷하나, 게시글 상세에 해시태그가 10개 이상(`#협업 #codebuddy #kris #AI리뷰 #ai-review #pr-agent #collaboration #release-risk #배포리스크 #장애예방 #risk-detecting`) 나열돼 있어 **키워드 스팸형 태깅** 인상을 준다.
- **컬러**: 파랑·보라·청록을 함께 쓰는 화려한 브랜드 컬러 팔레트. 홈 화면은 과감해서 개성 있지만, 기술 블로그로서는 다소 "놀이앱스럽게" 느껴질 수 있는 절충점이 있다.
- **AI 안티패턴 여부**: 해시태그 과다 나열은 체크리스트에 해당. 홈 히어로 자체는 사람이 공들여 만든 커스텀 콜라주라 AI스럽지 않지만, 글 목록의 썸네일 톤 불일치는 "아트 디렉션 없이 각자 대충 올린" 인상을 준다.
- **총평**: 브랜드 임팩트는 강하지만 **목록 화면의 썸네일 톤 불일치와 해시태그 과다**가 완성도를 갉아먹는다.

## 4️⃣ LY Corporation Tech Blog (구 LINE Engineering)

- **레이아웃 비율**: 같은 페이지 안에 두 종류의 레이아웃이 공존한다. 상단 "Latest Posts"는 제목만 나열한 **완전히 꾸미지 않은 텍스트 목록**(굵은 검정 구분선 하나로 구획)이고, 그 아래 "AI/Infrastructure/Frontend" 도메인별 섹션은 카드 그리드로 잘 정돈돼 있다. **한 화면에서 디자인 완성도가 상단과 하단이 뚝 끊긴다.**
- **이미지 배치**: "Latest Posts" 구간은 이미지가 전혀 없고, 아래 도메인 섹션은 짙은 그라디언트 배경에 카테고리 아이콘 + 굵은 흰 글씨로 통일된 키비주얼을 쓴다. 후자만 보면 완성도가 높지만, 전자와 한 페이지에 있어 이질감이 크다.
- **타이포그래피**: 카드 구간은 제목/부제/저자 위계가 뚜렷하고 여백도 넉넉하지만, 목록 구간은 폰트 크기 차이만으로 위계를 표현해 성의가 없어 보인다.
- **컬러**: 카드 섹션은 진한 청록·남색 그라디언트로 도메인마다 색을 구분해 세련됐다. 반면 목록 구간은 흑백뿐이라 같은 사이트라고 느끼기 어렵다.
- **AI 안티패턴 여부**: 체크리스트의 "한 페이지 안에 초안과 완성본이 섞인 인상"에 정확히 해당한다. 실제로는 두 섹션의 목적이 다르겠지만(빠른 색인 vs. 브라우징), 시각적으로는 "일부만 다듬고 나머지는 손을 안 댄" 것처럼 보인다.
- **총평**: 도메인 카드 섹션 하나만 놓고 보면 우수하지만, **페이지 전체의 디자인 밀도가 고르지 않다**는 점이 가장 큰 감점 요인.

## 5️⃣ 당근 기술 블로그 (Medium — medium.com/daangn)

- **레이아웃 비율**: 상단에 당근 특유의 주황색 브랜드 배너(일러스트 인물 + 당근 아이콘, "Opening Doors to Local Living")가 있어 첫인상은 나쁘지 않다. 그러나 배너 아래부터는 Medium의 표준 3열 카드 틀에 그대로 얹혀 있어 브랜드 색이 거의 사라진다.
- **이미지 배치**: 서로 다른 두 개의 글("Laying the Rails Beyond WebView: Why Karrot Chose Lynx", "웹뷰 다음의 레일을 깔다: 당근이 Lynx를 선택한 이유")이 **완전히 동일한 늑대머리 아이콘 일러스트를 썸네일로 재사용**하고 있다 — 체크리스트의 "같은 이미지를 다른 글에 그대로 재사용"에 정확히 해당하는 사례.
- **타이포그래피**: Medium 플랫폼 기본 서체(세리프 계열 제목 + 산세리프 본문)를 그대로 사용해, 당근마켓 고유의 서체·톤앤매너가 전혀 반영되지 않는다.
- **컬러**: 배너의 주황색을 제외하면 흰 배경 + 회색 텍스트뿐인 Medium 기본 팔레트. 브랜드 아이덴티티가 배너 한 장에만 갇혀 있다.
- **AI 안티패턴 여부**: 썸네일 재사용은 체크리스트에 정확히 해당. 또한 로그인하지 않은 방문자에게 "Sign up / Sign in" 버튼과 빈 회색 아바타 아이콘이 상단에 계속 노출되어, 자사 서비스가 아니라 **남의 플랫폼에 세 들어 사는 인상**을 준다.
- **총평**: 배너 하나만 커스텀했을 뿐, 실질적인 화면 대부분이 Medium 기본값이라 **브랜드 고유의 시각 정체성이 가장 약하다.**

## ✅ SFOOD IT Tech Blog에 대한 시사점

1. **목록 화면에 썸네일을 반드시 채워야 한다.** 우아한형제들과 LY Corp 사례처럼 이미지가 없거나 부실한 구간은 아무리 텍스트 품질이 좋아도 "심심하다"는 인상을 먼저 남긴다. `design-benchmark.md`가 이미 채택한 "썸네일 상단 + 태그 배지 + 제목 + 요약" 카드 구조를 목록 전 구간에 예외 없이 적용해야 한다.
2. **썸네일은 게시글마다 실제로 달라야 하며, 톤이 통일돼야 한다.** 카카오(톤 불일치)와 당근(완전 동일 이미지 재사용) 두 사례 모두 "썸네일에 신경 쓰지 않았다"는 인상을 주었다. Confluence 원본에 대표 이미지가 없는 문서라면, 임의 스톡컷을 붙이기보다 **일관된 브랜드 일러스트/플레이스홀더 시스템**(토스 방식)을 마련하는 것이 안전하다.
3. **한 화면 안에서 디자인 완성도가 갈리면 안 된다.** LY Corp처럼 "일부 섹션은 잘 만들고 일부는 방치"된 상태는 방문자에게 신뢰도를 떨어뜨린다. 목록/상세/댓글 등 Viewer의 모든 화면에 동일한 디자인 토큰(`design-system.md`)을 예외 없이 적용해야 한다.
4. **태그는 검색 편의를 위한 것이지 나열을 위한 것이 아니다.** 카카오처럼 해시태그를 10개 넘게 붙이면 오히려 정성 없이 자동 생성한 듯한 인상을 준다. `data-spec.md`에서 태그 개수에 상한을 두는 것을 고려한다.
5. **플랫폼에 종속되면 브랜드를 잃는다.** 당근/Medium 사례는 콘텐츠가 아무리 좋아도 자체 디자인 통제권이 없으면 브랜드 정체성이 배너 한 장에만 갇힌다는 것을 보여준다. 자체 Next.js 구축이라는 현재 방향을 유지해야 하는 이유이기도 하다.

## 🔎 시사점 반영 여부 점검 (2026-09-17, `mockups/blog-ui-benchmark.html` · `data-spec.md` 직접 확인)

| 시사점 | 상태 | 확인 내용 |
|---|---|---|
| 1. 목록에 썸네일 필수화 | ⚠️ 부분 반영 | 카드마다 썸네일 자리는 구조적으로 이미 있으나, 현재는 실제 이미지가 아니라 **그라데이션 블록 placeholder**다(목업 자체 안내문: "실제 이미지 대신 그라데이션 블록을 썸네일로 사용"). 구조는 맞지만, 실제 구현 단계에서 진짜 대표 이미지/일러스트 시스템으로 교체하지 않으면 이 문서가 지적한 "AI 안티패턴(그라데이션 블롭 남발)"을 우리 서비스가 그대로 재현하게 된다. **→ 미해결, 후속 작업 필요.** |
| 2. 썸네일 톤 통일 | ✅ 반영됨 | Backend=레드 계열, Culture=오렌지 계열, AI=블루 계열로 **카테고리별 색상이 코드화**되어 있어, 카카오 사례처럼 글마다 톤이 제각각인 문제는 없다. |
| 3. 화면 전체에 디자인 토큰 일관 적용 | ✅ 반영됨 | 목록·상세·댓글 화면 모두 동일한 라운드·타이포·여백 톤을 쓰고 있어, LY Corp처럼 한 페이지 안에서 완성도가 끊기는 문제는 재현되지 않는다. |
| 4. 태그 개수 상한 | ✅ 이미 해결됨 | `data-spec.md:66`에 "화면에는 순서상 앞의 최대 3개만 `·`로 이어 보여준다"고 명시돼 있어, 카카오처럼 해시태그가 10개 넘게 나열되는 문제는 스펙 단계에서 이미 차단됨. |

**결론**: 5개 중 4개는 이미 구조·스펙에 반영되어 있고, **유일하게 미해결인 것은 "①번 — 그라데이션 placeholder를 실제 썸네일 이미지로 교체하는 작업"** 이다. 이 작업 없이 현재 목업 그대로 배포하면, 이 문서가 지적한 "AI가 만든 느낌"의 그라데이션 블록 남발 문제를 SFOOD Tech Blog 스스로 재현하게 되므로 우선순위 있게 다뤄야 한다.

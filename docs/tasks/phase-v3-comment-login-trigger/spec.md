# Spec — Phase V3: 댓글 작성 인라인 로그인 트리거

## 목표

prd.md 화면 정의의 Comment 위젯에 명시된 "MS 계정으로 댓글 작성" 버튼(로그인 트리거)을 구현한다. 지금까지는 서버가 세션 유무만으로 `isLoggedIn`을 판단할 뿐, 로그인을 시작할 방법 자체가 Viewer 어디에도 없었다.

## 배경 — 함께 발견한 버그

Editor/Viewer 저장소 분리 과정에서 `src/app/api/auth/ax-callback/route.ts`가 로그인 성공 시 `redirectTo: "/editor"`로 하드코딩되어 있는 것을 확인했다. `/editor`는 이제 이 저장소에 존재하지 않으므로, 분리 이후로는 댓글 로그인을 시도해도 404로 끝나는 상태였다. 이번 작업에서 함께 고쳤다.

또한 `src/lib/auth.ts`의 `pages.signIn`도 삭제된 `/login`을 가리키고 있어, 로그인 실패 시 404로 이어지는 문제가 있었다 — `/`(홈)로 변경했다.

## 설계 — 돌아갈 위치를 어떻게 전달하는가

AX Auth의 `GET /auth/login/{clientId}`는 `redirect_uri`만 받고, 임의의 상태(state) 값을 그대로 왕복시켜 준다는 보장이 login-integration-guide.md에 없다(등록된 `redirect_uri`와 정확히 일치해야 할 가능성이 있어 쿼리 파라미터를 덧붙이는 것은 위험한 가정). 대신 클라이언트에서 로그인을 시작하기 직전에 **우리가 직접 쿠키(`ax_return_to`)에 현재 경로를 저장**하고, 콜백 라우트가 그 쿠키를 읽어 리다이렉트 대상으로 사용하는 방식을 택했다. AX Auth 쪽 동작에 대한 추가 가정이 필요 없는 가장 안전한 방법이다.

- 쿠키 값은 `/`로 시작하고 `//`로 시작하지 않는 상대 경로만 신뢰한다(오픈 리다이렉트 방지).
- 쿠키 `max-age`는 180초(AX Auth `login_token` TTL)보다 넉넉한 300초로 설정했다.

## 완료 기준

- `npm run lint`, `npm run build` 통과.
- 브라우저에서 게시글 상세 화면에 "MS 계정으로 댓글 작성" 버튼이 노출되는지 확인.
- 버튼 클릭 시 `ax_return_to` 쿠키가 정확한 게시글 경로로 설정되는지 확인.
- 버튼 클릭이 실제로 AX Auth를 거쳐 `login.microsoftonline.com`까지 도달하는지 확인(실 로그인 완료는 사용자가 직접 진행).

## 미확인 사항

- 실 계정으로 로그인을 끝까지 완료해 콜백이 정확한 게시글로 되돌아오는지는 검증하지 못했다(실 자격증명 입력은 AI가 대신하지 않음).
- 댓글 알림 메일 발송에 필요한 신선한 `login_token` 확보 UX는 이번 범위에 포함하지 않았다 — 이 로그인 트리거는 NextAuth 세션을 만드는 것이 목적이고, 세션 생성에 쓰인 `login_token`은 검증 시점에 이미 소비되어 메일 발송용으로 재사용할 수 없다(기존에 열려 있던 별도 과제).

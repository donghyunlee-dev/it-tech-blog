## 추가 검증 (2026-09-16, 사용자 승인 후 실제 댓글로 확인)

사용자가 "컴포넌트 테스트" 문서에 Confluence 네이티브 댓글 UI로 직접 댓글을 하나 남겼으나, 구조화 형식(`이름 | 이메일 | 댓글`)이 아니라 저희 파서가 의도적으로 건너뛴다는 것을 먼저 확인·설명했다(설계대로 동작 — 버그 아님). 사용자 승인을 받아 실제 블로그 댓글 폼(게이트→확인→작성)으로 테스트 댓글을 하나 남겨 전체 경로를 검증했다.

| 항목 | 방법 | 결과 |
|---|---|---|
| 실제 댓글 작성 | "컴포넌트 테스트" 상세 페이지에서 게이트 → "이름으로 계속하기" → 이름 `Claude 테스트`/이메일 `claude-agent-test@s-food.com` 입력 → 확인 → 댓글 등록 | 성공, 해당 페이지 댓글 수 "댓글 1개"로 반영, 제출 에러 없음 |
| 사이드바 반영 | 홈 화면 재방문 | "최근 댓글"에 방금 작성한 댓글의 인용문·작성자(`Claude 테스트`)·글 제목(`컴포넌트 테스트`)이 정상 노출됨. 콘솔 에러 없음 |

**결론: `listRecentComments` 및 사이드바 렌더링 전체 경로가 실제 데이터로 end-to-end 검증됐다.**

## 검증하지 못한 것

- **부분 실패 시나리오**(게시 문서 중 하나만 댓글 조회 실패)는 코드 리뷰로만 확인했다(`try/catch`로 개별 문서 실패를 빈 배열로 흡수, 전체 실패로 번지지 않음) — 실제 API 실패를 인위적으로 재현하지는 않았다.

# result — 사이드바 "최근 댓글" 실데이터

## 요약

홈 화면 사이드바 "최근 댓글"에 실데이터를 연결했다. Confluence API가 스페이스 전체를 가로지르는 댓글 조회를 제공하지 않아, 게시 문서마다 개별 조회한 뒤 메모리에서 합쳐 최신순 정렬하는 방식으로 구현했다("소규모 팀" 규모 전제, architecture.md 참고).

## 변경 파일

- `src/lib/comments/comments.ts` — `listRecentComments(posts, limit)` 추가: 게시 문서별 병렬 조회, 구조화 본문 파싱, 60자로 자른 인용문(`quote`), 최신순 정렬 후 상위 N개(기본 4개) 반환. 문서 하나의 조회가 실패해도 나머지는 정상 반환(부분 실패 허용).
- `src/app/page.tsx` — `listRecentComments` 호출, `RecentCommentsSidebar`에 실제 데이터 전달.

## 검증

- `npm run lint`/`npm run build` 통과
- 실 게시 문서(댓글 0건 상태)로 사이드바가 정상적으로 렌더링되지 않는 것 확인, 콘솔 에러 없음
- **사용자 승인 후 실제 댓글 작성으로 end-to-end 검증 완료**: "컴포넌트 테스트" 문서에 블로그 댓글 폼(게이트→확인→작성)으로 테스트 댓글을 남겨, 홈 화면 사이드바에 인용문·작성자·글 제목이 정상 노출되는 것까지 확인했다.
  - 부수 발견: 사용자가 먼저 Confluence 네이티브 댓글 UI로 직접 남긴 댓글은 구조화 형식(`이름 | 이메일 | 댓글`)이 아니라 우리 파서가 의도적으로 건너뛰었다 — 버그가 아니라 "댓글은 반드시 블로그 폼을 거쳐야 작성자를 식별할 수 있다"는 기존 설계(architecture.md) 그대로의 동작임을 확인·설명했다.
- 상세는 [test-result.md](test-result.md) 참고

## 열린 과제

- 게시 문서 수가 늘어나면 홈 화면 로드 시 문서 수만큼 댓글 조회 API 호출이 늘어난다 — 현재 규모(3건)에서는 문제 없으나, 문서가 수십 건 이상으로 늘면 재검토가 필요하다(예: 최근 게시된 N개 문서만 조회하는 식으로 범위를 좁히는 것을 고려할 수 있다).
- Confluence 네이티브 댓글 UI로 직접 남긴 댓글이 블로그에서 완전히 무시된다는 점은 편집자/운영자에게 안내가 필요할 수 있다(현재는 콘솔 로그로만 남고 사용자에게는 어떤 안내도 없음).

# spec — 최근 댓글 조회 범위 제한

## 문제 정의

viewer-recent-comments의 열린 과제: "게시 문서 수가 늘어나면 홈 화면 로드 시 문서 수만큼 댓글 조회 API 호출이 늘어난다 — 현재 규모(3건)에서는 문제 없으나, 문서가 수십 건 이상으로 늘면 재검토가 필요하다(예: 최근 게시된 N개 문서만 조회하는 식으로 범위를 좁히는 것을 고려할 수 있다)."

`src/app/page.tsx`는 현재 `listPublishedPosts()`가 반환하는 **전체** 게시 문서를 `listRecentComments(posts, limit)`에 그대로 넘기고, `listRecentComments`는 그 목록 전체에 대해 Confluence 댓글 조회를 병렬 호출한다. 사이드바에 실제로 보이는 건 상위 4개뿐인데도, 게시 문서가 늘어날수록 홈 화면 로드 시 필요 이상으로 API 호출이 늘어난다.

## 범위 (In Scope)

- 홈 화면이 `listRecentComments`에 넘기는 게시 문서 목록을 "최신순 상위 N건"으로 제한한다(전체가 아니라).
- 이 스캔 범위(N)를 사이드바 표시 개수(4)보다 넉넉하게 잡아, 가장 최근 게시물 몇 개에 댓글이 없더라도 사이드바가 비어 보이지 않게 한다.

## Out of Scope

- Confluence API 자체의 캐시 계층(Redis 등) 도입 — architecture.md의 기존 방침대로 필요성이 실증되기 전까지는 ISR 캐시로 충분하다고 본다.
- 스캔 범위 값의 정교한 튜닝(A/B 테스트 등) — 합리적인 기본값을 코드 주석과 함께 정하고, 실사용 데이터가 쌓이면 조정 가능하도록 상수로 둔다.

## 수용 기준

- [ ] 게시 문서 수와 무관하게, 홈 화면 로드 시 댓글 조회 API 호출 횟수가 고정된 상한(스캔 범위 N) 이하로 유지된다.
- [ ] 실 데이터(3건)에서 사이드바에 기존과 동일하게 댓글이 노출된다(회귀 없음).
- [ ] `npm run lint`/`npm run build` 통과.

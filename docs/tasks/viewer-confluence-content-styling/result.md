# result — Confluence 본문 요소 스타일 복구

## 요약

사용자가 "안티패턴을 분명 제외시켰는데 다시 나오는 것 같다"고 지적한 증상을 실제 게시 문서로 재현·확인했다. 정확히는 이전에 고쳤던 그라데이션/호버 문제가 재발한 것이 아니라, **2026-09-15 `@sfood/ui` 도입 시 추가한 Tailwind Preflight가 제목·목록·인용문의 브라우저 기본 스타일을 초기화**하면서 본문 요소들이 전부 같은 크기로 뭉개진, 같은 성격("균일한 크기")의 새 회귀였다. `globals.css`에 `.article-body` 하위 표준 HTML 요소(제목/목록/인용문/링크/구분선/인라인 코드) 스타일을 추가해 복구했다.

## 추가 회귀 3건 (2026-09-16, "컴포넌트 테스트" 문서로 재점검하며 발견)

사용자가 다양한 서식을 담은 실제 문서("컴포넌트 테스트")를 추가로 게시해 재점검한 결과, 세 가지를 더 발견해 같은 파일(`globals.css`)에서 수정했다.

1. **클래스 없는 순정 `<pre><code>`가 스타일 없이 렌더링됨**: `converter.ts`는 Confluence의 "코드" *매크로*만 `.viewer-code` 클래스를 붙이는데, Editor 자체 코드 블록은 매크로를 거치지 않고 클래스 없는 `<pre><code>`로 그대로 나오는 경우가 실제로 있었다. 직전 라운드에 추가한 `.article-body pre code { background: none; ... }`(매크로 코드 블록의 이중 스타일 방지용)가 이런 순정 `<pre>`에도 적용되면서, 배경·패딩·라운드가 아예 없는 코드 블록이 나왔다. `.article-body pre`(클래스 무관)에 직접 배경/패딩/라운드를 주는 방식으로 수정해 두 경우 모두 같은 모양이 되도록 했다.
2. **빈 `<p></p>`가 22px 여백을 그대로 먹어 빈 공백이 쌓임**: Confluence storage format에 흔한 빈 문단 태그를 숨기지 않고 있었다(`p:empty { display: none; }` 추가).
3. **본문 첫 요소가 제목(`<h2>`)일 때 리드 문단 스타일이 잘못 씌워짐**: 리드 문단 강조 규칙이 `.article-body > *:first-child`로 요소 종류를 가리지 않고 있어서, 문서의 첫 요소가 우연히 제목이면 제목이 옅은 회색·중간 굵기로 눌려 오히려 바로 아래 `h3`보다 흐리게 보이는 버그가 있었다. `.article-body > p:first-child`로 좁혀 문단일 때만 적용되도록 고쳤다.

### 검증

- `npm run lint`/`npm run build` 통과
- "컴포넌트 테스트" 문서에서 `getComputedStyle`로 재확인: `pre` 3개 모두 배경·패딩·라운드 정상, 빈 `<p>` 8개 모두 `display:none`, `h2`(문서 첫 요소) 24px/700/검정으로 정상.
- 기존 문서("Gemini에 SFOOD 업무 지침 설정하기", 첫 요소가 실제 `<p>`)에서 리드 문단 스타일이 여전히 정상 적용되는지 회귀 확인 완료.

### 참고: "카드 섹션 왼쪽 컬러 라인"에 대한 확인

같은 시점에 사용자가 "카드 섹션의 왼쪽 컬러 라인이 안티패턴 아니냐"고 물어 확인했다. 실측 결과 `.post-card`(최신 글 카드)는 `border-left: 0`으로 왼쪽 라인이 전혀 없고, 왼쪽에 4px 브랜드레드 라인이 있는 것은 히어로 박스(`.hero`)뿐이었다 — design-direction.md가 승인한 시그니처 요소 ③(히어로)이다. 925studios 원문을 다시 확인했으나 "colored left border/accent line"은 그 글의 안티패턴 목록(Inter 폰트, 보라-파랑 그라데이션, 모호한 헤드라인, 스톡 이미지, 균일한 크기, 마이크로 인터랙션 부재, 제네릭 호버, 일관된 페이드인 애니메이션)에 없다 — 안티패턴 아님으로 확인.

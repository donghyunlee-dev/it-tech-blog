# spec — 태그 기반 필터링/검색

## 문제 정의

viewer-tag-labels에서 태그 표시만 구현하고 "태그 기반 필터링/검색(카테고리 pill row + 카운트 표시)"은 범위에서 제외하며 "검색 오버레이(CommandPalette)에 태그 필터를 추가하려면 별도 작업이 필요하다"고 남겨두었다. `@sfood/ui`의 `CommandPalette`는 `groups`(그룹별 `label`/`description` 텍스트)만 받고 커스텀 필터 UI(pill row) 슬롯은 제공하지 않으므로, 실제 컴포넌트 API 안에서 구현 가능한 형태로 범위를 정한다.

## 설계 방향

- **검색 오버레이**: "게시글" 그룹 옆에 "태그" 그룹을 추가한다. 각 태그를 `태그명 (건수)` 형태의 항목으로 보여주고, 선택하면 그 태그의 게시글만 모은 아카이브 페이지로 이동한다(팔레트 자체에 필터 UI를 얹는 대신, 팔레트의 기존 텍스트 검색이 태그 라벨에도 자연히 적용되게 한다 — "AI"를 입력하면 태그 항목과 제목에 "AI"가 들어간 게시글이 함께 걸러진다).
- **태그 아카이브 페이지**(`/tags/[tag]`, 신규): 해당 태그가 붙은 게시글만 홈과 동일한 카드 그리드로 보여준다.
- **상세 페이지 태그 링크**: `/posts/[slug]`의 태그 라인(키커)을 각 태그별 링크로 바꿔 클릭하면 아카이브 페이지로 이동한다. 홈 화면 카드/히어로의 키커는 카드 전체가 이미 게시글 링크로 감싸여 있어(`<Link>` 중첩은 유효하지 않은 HTML이 됨) 이번 범위에서는 그대로 두고 클릭 가능하게 만들지 않는다.

## 범위 (In Scope)

- `GET /api/viewer/posts` 응답에 `tags: string[]` 추가(검색 오버레이가 태그 목록·건수를 계산하는 데 필요) 및 `api-spec.md` 갱신.
- `src/app/tags/[tag]/page.tsx` 신규 — 태그별 게시글 아카이브.
- `src/components/layout/SearchOverlay.tsx` — "태그" `CommandGroup` 추가.
- `src/app/posts/[slug]/page.tsx` — 키커의 태그를 아카이브 페이지 링크로 변경.

## Out of Scope

- 홈 화면 카드/히어로 키커를 클릭 가능하게 만드는 것(중첩 링크 문제로 이번 범위에서 제외).
- 태그 아카이브 페이지를 `sitemap.xml`에 포함하는 것 — 파생 목록 페이지라 이번 SEO 스코프에는 넣지 않는다(필요해지면 별도 검토).
- 여러 태그를 동시에 선택하는 AND/OR 조합 필터 — 한 번에 하나의 태그만 본다.
- 팔레트 자체에 커스텀 pill row UI를 그리는 것 — `@sfood/ui`가 지원하지 않아 그룹/항목 방식으로 대체한다.

## 수용 기준

- [ ] 검색창(Cmd/Ctrl+K)에 "태그" 그룹이 보이고, 각 항목이 `태그명 (건수)` 형태다.
- [ ] 태그 항목을 선택하면 `/tags/{태그}`로 이동하고, 그 태그가 붙은 게시글만 보인다.
- [ ] 검색창에 태그명을 입력하면(예: "ai") 해당 태그 항목과 제목에 일치하는 게시글이 함께 필터링된다.
- [ ] 게시글에 태그가 하나도 없으면 "태그" 그룹 자체가 보이지 않는다.
- [ ] 존재하지 않거나 게시글이 없는 태그로 접근하면 빈 상태 안내가 뜬다(오류가 아님).
- [ ] 상세 페이지 태그를 클릭하면 해당 아카이브 페이지로 이동한다.
- [ ] `npm run lint`/`npm run build` 통과.

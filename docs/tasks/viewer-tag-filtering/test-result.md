# test-result — 태그 기반 필터링/검색

| 항목 | 방법 | 결과 |
|---|---|---|
| Lint | `npm run lint` | 통과 |
| 빌드 | `rm -rf .next && npm run build` | 통과, `/tags/[tag]` 라우트가 동적 라우트로 정상 포함됨 |
| `GET /api/viewer/posts` | curl | 각 게시글 항목에 `tags: string[]` 포함 확인(예: `["ai","업무","활용"]`, 태그 없는 문서는 `[]`) |
| `/tags/ai` | curl + grep | 태그 "ai"가 붙은 실 게시 문서 2건(ChatGPT/Gemini)만 포함, 태그 없는 "컴포넌트 테스트"는 제외됨 |
| `/tags/AI`(대소문자) | curl | 소문자 `ai`와 동일한 2건을 그대로 반환 — 대소문자 무관 매칭 확인 |
| `/tags/no-such-tag` | curl | `200`, "이 태그가 붙은 게시글이 없습니다" 빈 상태 안내(오류 아님) |
| 검색 오버레이 "태그" 그룹 | 브라우저(Cmd/Ctrl+K, `preview_start` dev) | "게시글" 그룹 아래 "태그" 그룹이 시각적으로 렌더링됨(`업무 (2)`, `활용 (2)`, `ai (2)`) — 접근성 트리 요약에는 그룹 레이블이 누락돼 보였으나 스크린샷으로 실제 렌더링 확인 |
| 태그명 텍스트 검색 | 검색창에 "ai" 입력 | "게시글" 그룹은 결과 없음(제목에 "ai" 없음), "태그" 그룹의 "ai (2)"만 남는 것을 확인 — 팔레트의 기본 텍스트 필터가 태그 라벨에도 그대로 적용됨 |
| 태그 항목 선택 | "ai (2)" 클릭 | `window.location.href`가 `/tags/ai`로 이동, 탭 타이틀이 "#ai — SFOOD IT Tech Blog"로 변경, 해당 태그의 게시글만 렌더링됨 확인 |
| 상세 페이지 태그 링크 | 실 게시 문서 상세에서 "업무" 태그 클릭 | `href="/tags/%EC%97%85%EB%AC%B4"`로 렌더링, 클릭 시 `/tags/업무`로 이동·필터링 확인. 브랜드 레드 키커 스타일 유지(전역 `a` 색상 리셋에 덮어쓰이지 않음) |
| 콘솔 에러 | `read_console_messages`/`read_network_requests` | 현재 세션(포트) 요청에는 오류 없음(다른 세션에서 남은 것으로 보이는 무관한 404 로그 1건 확인, 이번 변경과 무관) |

## 커버되지 않은 부분

- 홈 화면 카드/히어로의 키커는 spec.md에서 명시한 대로 이번 범위에서 클릭 가능하게 만들지 않았다(카드 전체가 이미 게시글 링크로 감싸여 있어 중첩 `<Link>`가 되는 문제 때문).
- 태그 아카이브 페이지는 `sitemap.xml`에 포함하지 않았다(spec.md의 Out of Scope).

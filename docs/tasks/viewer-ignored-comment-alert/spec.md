# spec — 무시된 Confluence 네이티브 댓글 운영 알림

## 문제 정의

viewer-recent-comments의 열린 과제: "Confluence 네이티브 댓글 UI로 직접 남긴 댓글이 블로그에서 완전히 무시된다는 점은 편집자/운영자에게 안내가 필요할 수 있다(현재는 콘솔 로그로만 남고 사용자에게는 어떤 안내도 없음)." — 댓글은 반드시 블로그 폼(게이트→확인→작성)을 거쳐야 작성자를 식별할 수 있는 구조화 형식(`이름 | 이메일 | 댓글`)으로 저장되는데, 누군가 Confluence 화면에서 직접 댓글을 남기면 이 형식이 아니라서 블로그 어디에도 노출되지 않는다. 이는 버그가 아니라 기존 설계(architecture.md)지만, 편집자 입장에서는 "댓글을 남겼는데 왜 안 보이지"를 알아챌 방법이 서버 콘솔 로그뿐이었다.

추가로 조사해보니 `listComments`(문서 상세 댓글 조회)는 건너뛸 때 `console.error`를 남기지만, `listRecentComments`(홈 사이드바 최근 댓글)는 같은 상황에서 로그조차 남기지 않는 비일관성이 있었다.

## 범위 (In Scope)

- Viewer가 이미 운영 알림에 쓰고 있는 Slack 채널(`sendSlackAlert`)에, 구조화 형식이 아니라 건너뛴 댓글을 감지하면 알린다.
- `listComments`/`listRecentComments` 양쪽 모두 동일하게 알림을 트리거하도록 통일한다.
- 같은 댓글을 반복 알리지 않도록 최소한의 중복 제거를 적용한다(자체 DB가 없으므로 메모리 기반 — 완벽한 항구적 중복 제거는 아님).

## Out of Scope

- Editor 저장소에 "무시된 댓글" 목록을 보여주는 화면을 추가하는 것 — Editor는 별도 저장소이고 이 저장소의 범위가 아니다.
- Confluence 네이티브 댓글을 파싱해 억지로 블로그에 표시하는 것 — 작성자를 신뢰성 있게 식별할 방법이 없어 여전히 불가능하다(기존 설계 유지).
- 알림 채널을 Slack 외의 다른 수단(이메일 등)으로 확장하는 것.

## 수용 기준

- [ ] 구조화 형식이 아닌 댓글이 발견되면(상세 페이지 조회든 홈 사이드바 조회든) 운영 Slack 채널에 pageId·commentId를 포함한 안내 메시지가 전송된다.
- [ ] 같은 프로세스 안에서 동일한 commentId는 한 번만 알린다(반복 페이지 로드마다 스팸처럼 알리지 않음).
- [ ] Slack 전송 자체가 실패해도 댓글/최근 댓글 조회 자체는 정상 동작한다(알림 실패가 열람을 막지 않음).
- [ ] `npm run lint`/`npm run build` 통과.

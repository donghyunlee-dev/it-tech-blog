# spec — 댓글 알림 메일용 신선한 login_token 확보

## 문제 정의

phase-v3-comment-login-trigger에서 "MS 계정으로 댓글 작성" 로그인 트리거를 구현했지만, 그 로그인에 쓰인 `login_token`은 NextAuth 세션 생성(`authorize()`의 `verifyLoginToken` 호출)에 이미 소비된 뒤라 댓글 알림 메일 발송에 재사용할 수 없었다([src/lib/comments/notify.ts:16-18](../../../src/lib/comments/notify.ts)에 알려진 제약으로 기록되어 있었음). 그 결과 세션이 이미 있는 상태(두 번째 댓글부터)로 작성한 댓글은 항상 알림 메일이 건너뛰어졌다.

## 해결 방향(사용자 확정)

login-integration-guide.md/mail-integration-guide.md에 따르면 `login_token`의 "세션 검증(verify)"과 "메일 발송(mail-send)" 사용 횟수는 **서로 독립적으로 소비**된다. 따라서 팝업 재인증 같은 새 UI를 추가하지 않고, 이미 구축된 AX Auth **리다이렉트** 흐름을 댓글 저장 시마다 재사용한다:

1. 댓글을 저장할 때(MS 로그인 사용자), 작성 중이던 내용을 짧게 쿠키에 담아두고 AX Auth 로그인 URL로 리다이렉트한다. 브라우저에 활성 MS 세션이 남아 있으면 대부분 화면 깜빡임 없이 즉시 콜백으로 돌아온다.
2. 콜백은 이번엔 세션을 새로 만드는 것이 목적이 아니다(이미 로그인되어 있었음) — 방금 받은 신선한 `login_token`을 그 자리에서 검증해 댓글을 생성하고, 같은 토큰의 남은 메일 발송 예산으로 문서 작성자에게 알림 메일을 즉시 보낸다.

## 범위 (In Scope)

- `src/app/api/auth/ax-callback/route.ts`: 대기 중인 댓글 초안 쿠키가 있으면 "댓글 생성 + 메일 발송"을 이 자리에서 완료하는 분기 추가. 없으면 기존 로그인 트리거 동작(변경 없음).
- `src/components/comments/CommentSection.tsx`: MS 로그인 사용자의 댓글 저장 시(매번), 초안을 쿠키에 담고 AX Auth로 리다이렉트하도록 변경. 외부 사용자(비로그인) 흐름은 변경 없음.
- 인증 실패로 작성 중이던 댓글 내용이 유실될 수 있는 새 리스크에 대응해, `/posts/[slug]`에 `?error=...` 안내 배너를 최소 범위로 추가(기존에는 쿼리 파라미터만 붙고 화면에 아무 표시도 없었음).
- `docs/product/prd.md`의 Phase V3 진행 상태 문구 갱신.

## Out of Scope

- 외부(비로그인) 사용자 댓글 — mail-integration-guide.md가 이 알림을 MS 로그인 사용자 전용으로 명시하고 있어 변경 없음.
- 팝업 기반 재인증(대안으로 검토했으나 채택하지 않음 — 기존 리다이렉트 인프라 재사용이 더 단순함).
- `?error=` 배너의 세분화된 에러 메시지 체계 — 알려진 코드 2개(`missing_token`, `comment_failed`)에 대한 간단한 매핑과 그 외 코드에 대한 공용 fallback 문구만 제공한다.

## 수용 기준

- [ ] 이미 로그인된 상태에서 댓글을 저장하면(두 번째 댓글부터도) 문서 작성자에게 알림 메일이 발송된다(문서 작성자 이메일이 있는 경우).
- [ ] 이 과정에서 사용자가 보는 화면은 짧은 리다이렉트 왕복 외에 특별한 조작을 요구하지 않는다(팝업/추가 버튼 없음).
- [ ] 리다이렉트 도중 인증에 실패하면 댓글은 저장되지 않고, 화면에 재입력을 안내하는 문구가 보인다(내용이 조용히 사라지지 않음).
- [ ] 외부 사용자 댓글 작성 흐름과 API 라우트(`POST /api/comments`) 직접 호출 경로는 회귀 없음.
- [ ] `npm run lint`/`npm run build` 통과.

## 엣지 케이스

- 댓글 본문이 매우 길어 쿠키 크기 한도(약 4KB)를 넘으면, 리다이렉트 왕복 없이 기존처럼 즉시 저장하되 이번 댓글에 한해 알림 메일은 건너뛴다(저장 자체는 항상 보장).
- 리다이렉트 도중 브라우저가 실제 Microsoft 로그인 화면을 보여줘야 하는 경우(로컬 MS 세션이 만료된 경우) — 무중단은 아니지만 사용자가 다시 로그인하면 정상 완료된다. 별도 처리 불필요.
- AX Auth 서버 자체 실패(네트워크 오류 등)로 검증이 실패하면 댓글은 저장되지 않는다 — 기존에도 로그인 자체가 이 서버에 의존하므로 새로 생기는 리스크가 아니다.
